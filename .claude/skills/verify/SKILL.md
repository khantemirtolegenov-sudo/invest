# Проверка изменения

Останавливайся на первом провале, чини, начинай уровень заново.

## Уровень 1 — статика (всегда)

```bash
npm run typecheck   # сторож прав check:acl + tsc
npm run build
```
Backend без TS: `node --check <файл>` для изменённых файлов или короткий запуск (уровень 2).

## Уровень 2 — живой стенд (менялся runtime-код)

1. `npm run dev` в фоне; дождаться `:5185` и vite `:5184`. `GET http://localhost:5185/api/health` → 200.
2. Токен админа: `POST /api/auth/login` с SEED_ADMIN_* из `backend/.env` (только локальная база).
3. Изменённый сценарий через API: `GET /api/db`, `POST /api/db/sync` с нужными upserts → 200.
4. **Права:** второй пользователь с ролью employee (создать через `POST /api/auth/users` админом) —
   запрещённая запись даёт 403, закрытая коллекция приходит в снапшоте пустой. Без токена — 401.
5. Round-trip: созданная запись после повторного `GET /api/db` — со всеми полями.

## Уровень 3 — интерфейс (менялся экран)

Под тестовым админом на localhost (если владелец разрешил вход в браузере): открыть экран,
пройти сценарий, три состояния (загрузка / ошибка / пусто), консоль без ошибок, F5 — данные на месте.

## Отчёт

Проверено (с цифрами и кодами ответов) · Упало (команда, ошибка, файл:строка) · Не проверено (что и почему).
