## Первый запуск (если нет файла `.setup.json`)

Проект ещё не настроен. Прежде чем писать код, проведи с владельцем короткое интервью и
запусти мастер с ответами:
1. Как называется портал и для чего он — одной фразой. Короткое имя латиницей.
2. Модули: самостоятельная регистрация? Telegram-уведомления? загрузка файлов? Docker? CI?
3. Email первого администратора и строка подключения к PostgreSQL (по умолчанию локальная).
4. Какие 1–3 инструмента нужны первыми: название, какие данные (поля), кому доступ
   (admin — админ + грант, manager — руководители, all — все).

```bash
npm run setup -- --yes --name "…" --slug … --purpose "…" --modules registration,telegram,files,docker,ci --admin-email … --tools "id|Название|title:text,amount:float|admin"
```
Затем `npm run install:all`, создать базу, `npm run db:seed`, `npm run dev`.

## Бриф перед любой задачей

Если в просьбе нет — уточни 3–5 пунктов: что на входе (данные, источник), что на выходе
(экран, файл, уведомление), для кого (роль, доступ), объём, где показать результат.
Внешний сайт или API — сначала проверь, что он доступен и что отдаёт. Главная потеря
времени — переделки по неясной задаче, а не скорость кода.

## Архитектура данных — прочитай, прежде чем трогать

1. При входе фронтенд грузит **весь снапшот базы** (`GET /api/db`) в кэш вкладки (`app/src/api/db.ts`).
2. Сервисный слой `app/src/api/modules/*.ts` (инструмент = файл) **синхронно** читает
   `loadDb()` и меняет `mutate(fn)` кэш. Вся бизнес-логика — здесь.
3. Через ~250 мс дифф по коллекциям уходит пакетом в `POST /api/db/sync`. Неотправленное
   переживает F5 (ящик в localStorage), отказ сервера сохраняет всё, что можно (`salvage`).
4. Сервер проверяет права **на каждую сущность** (`backend/src/db/collections.js → checkWrite`)
   и пишет в типизированные таблицы (`backend/src/db/tables/simple.js → flatTable`).
5. Живое обновление: вкладка раз в 5 с спрашивает ревизию и перечитывает снапшот, если
   данные изменились (не под руками у пользователя).

**Контракт `GET /api/db` и `POST /api/db/sync` не менять.** Форма снапшота = интерфейс `Database`.

Следствия:
- В сервисном слое нет `fetch` для бизнес-операций (исключения: вход, файлы, Telegram).
  Метод = `await delay()` → все проверки и валидация → `mutate()` → **копия** наружу (`copy()`).
- Отказ — `throw new ApiError('Понятный текст по-русски')`, до первой записи.
- У каждой сущности array-коллекции есть `id` (`uid('префикс')`), даты — ISO-строки.
- Действие, о котором человеку говорят «отправлено», ждёт сервер: `confirmSync()`.

## Коллекция живёт в четырёх местах — заводи генератором

Тип (`app/src/types/index.ts`) + `Database` (`app/src/api/seedDb.ts`) · права сервера
(`COLLECTIONS` в `collections.js`) · таблица (миграция `backend/migrations/NNN_*.sql` +
`flatTable` в `simple.js`). **Новый инструмент — только `npm run new-tool`**, руками —
лишь смена формы существующей коллекции. Метки `@gen:*` не удалять. Миграции append-only:
применённый файл не правится, только новый номер.

## Права проверяются ДВАЖДЫ

Клиент (`app/src/utils/permissions.ts`) — UX. Сервер (`collections.js`) — безопасность.
Меняешь модель доступа — меняй обе стороны и проверь запросом, что запрещённое даёт 403.
Новый инструмент по умолчанию — **только админ + персональный грант** (`ADMIN_ONLY_TOOLS`).
Роли: `employee < manager < admin`. Не-админ не меняет себе `PROTECTED_USER_FIELDS` —
сервер молча восстанавливает их. Хеш пароля никогда не покидает backend.

## Конвенции

- У каждого файла JSDoc-шапка «что это и почему так». Комментарии — причины, не пересказ.
- Страницы — именованные экспорты, lazy через `named()` в `App.tsx`, под `RequireTool`/`RequireAdmin`.
- **UI: только токены** `tailwind.config.js` (цвета, `text-headline-md`, `text-body-sm`,
  `glass-card`, `p-card-padding`) и компоненты `app/src/components/ui`. Сырые hex и px — нельзя.
  Mobile-first, desktop — `lg` (1100px).
- Каждый экран рисует три состояния: загрузка, ошибка с «Повторить», пусто. Успех —
  `toast.success`, отказ — `toast.error(e.message)`.
- localStorage: токен, ящик неотправленного и личные удобства с ключом `hub.*`. Данные — только в базе.
- Git: фиче-ветки, conventional commits по-русски (`feat(deals): …`). **Пуш — только по
  явной команде владельца** в текущем сообщении («пушь», «мердж и пуш»).

## Планка качества

1. `npm run typecheck` и `npm run build` — без ошибок; CI зелёный.
2. Новый метод: delay, проверки до записи, ApiError по-русски, копия наружу, `updatedAt/updatedBy`.
3. Изменение доступа — обе стороны, запрещённое реально даёт 403 (проверено запросом).
4. Новая коллекция — генератором; round-trip: создал в интерфейсе → F5 → все поля на месте.
5. Новый экран — три состояния, маршрут под guard-ом.
6. Живой прогон: `npm run dev`, вход, изменённый сценарий, в консоли браузера нет ошибок.
7. Документация инструмента — `docs/tools/<id>.md` (история и решения — там, не здесь).
